
## 扩写卷二 第一章 代码级设计说明（面向论文“详细设计”章）

本节按照软件工程课程对“详细设计”的要求，将仓库内主要编译单元与头文件职责进行展开，便于评阅人把文字与目录树中的文件名对应起来。需要说明：下列描述以当前版本源码为准；若读者检出不同提交，应以 `git show` 或差异对比为准。

### 1.1 `testGrab.cpp` 作为集成测试与演示入口

`main` 函数完成资源获取与长期循环。其首先构造 `RemoteAPIClient client` 并取得 `sim` 句柄，这是整个控制平面的根。`findUR5JointHandle` 与 `findRG2JointHandle` 将场景树中的关节对象解析为可操作的句柄数组，这一层抽象避免在控制律中硬编码对象名称的字符串常数，除主程序中仍显式使用 `/UR5` 与 `attachPoint` 等路径外，大部分关节批处理以数组下标进行。步进模式启动后，程序再建立第二、第三套 `RemoteAPIClient` 专用于视觉侧，这种设计在工程上可能用于网络隔离或避免同一线程上远程调用的重入问题，代价是需管理多路 `stopSimulation` 的成对调用。若未正确停止，会造成悬挂连接或进程退出时资源未释放的警告。

随机数部分使用 `std::mt19937` 与均匀分布，对平面 x、y 与颜色索引进行采样。选择该引擎而非 `rand()` 的原因在于可复现性和统计性质更好，但本程序未设置固定种子。论文若需“同一组位姿的对比实验”，可以在 `main` 开始处增加 `gen.seed(12345)` 并记录。

主循环中 `removeObject` 与 `createPrimitiveShape` 组合实现“每轮新目标”。`setObjectInt32Param` 对 `shapeintparam_static` 与 `shapeintparam_respondable` 的配置会改变物体在 Bullet 中的参与方式：静态对象不移动但可参与某些交互，具体语义以 Coppelia 文档为准。在抓取前将物体视为易于稳定成像的静态体，在释放后切为可动力学演化，是任务层对“阶段不同、物理角色不同”的显式管理。

### 1.2 `visual_module` 的并发与数据一致性

`get_rgb_picture` 在互斥内设置 `rgb_requested` 并拉流，结束后以条件变量通知。`get_depth_picture` 对称。`get_share_rgb_picture` 对主线程无锁快速读共享图，但空图时返回空 `Mat`，主程序应判空；当前 `detectObject3D` 在 `image.empty()` 时返回无效点。`detectObject3D` 在取深度前 `depth_ready.wait`，其谓词为 `depth_data_ready` 为真。需要警惕：若深度线程因异常未再更新，主线程会阻塞。工程上可加入超时与错误恢复；本科论文可在此写“有限等待 + 失败返回”的改进设计。

反投影式中 `index = (511 - center_y) * 512 + center_x` 与固定分辨率 512 绑死。若场景修改传感器分辨率，必须同步修改该式与 `shared_resolution` 使用方式，否则出现深度与 RGB 错配。推荐改进为 `index = (H-1 - center_y) * W + center_x` 并读 `shared_resolution[0/1]`。

`point_cam2base` 的静态局部变量 `T_base_from_cam` 在首次成功加载后缓存。该模式在单任务长期运行中有效；若标定文件在运行期被更新，不会热重载。对实验无影响，对开发调试需进程重启。

### 1.3 `jacobian_cartesian_control` 的数值分析注意点

`buildJacobianPositionFd` 对每一列做前向差分。前向差分在步长趋近零时方差与步长成反比地放大测量噪声，在步长较大时截断误差上升。中心差分可二阶精度，但每列需两次扰动，仿真步数翻倍。`settleArmToTargets` 的步数与容差在差分阶段与主迭代阶段不同，是性能与精度折中。`invert3` 对 3x3 解析求逆，条件数在 `det` 极小时失败；`dlsStep` 在求逆失败时回退到简化的雅可比转置乘误差比例步长，属鲁棒性补丁，但理论收敛性无保证，论文中可注明为“工程回退”。

`clipVectorL2` 保证每步关节增量有界。无此限制时，在误差大处可能一次跨越多义解区域，导致轨迹不可预测。远距增益与 L2 裁剪一起作用，形成近似的“速度规划”效果。

### 1.4 `control` 模块的轨迹生成

`ur5_moveToJointTargetSmooth` 在相邻两段线性插值之间调用 `ur5_control` 并步进，本质是关节空间分段直线。它不包含速度曲线平滑（S 曲线或梯形），因此对加速度突变更敏感；若关节伺服内置加速度限制效果良好，则分段线性可用。若仍抖动，可增大 `segments` 与 `steps_per_segment`。这与注释中“带载回零更稳”一致。

`rg2_control` 对 `setJointTargetForce` 与 `setJointTargetVelocity` 的联合使用，需要参考 Coppelia 对 RG2 关节动力学的解释。力过大可能夹坏物体，过小可能滑脱；本课题以仿真为主，一般通过试凑确定。

## 扩写卷二 第二章 与课程知识点对照（机器人学、控制、计算机视觉）

### 2.1 机器人学：从雅可比到可操作性

在六自由度机械臂中，三乘六雅可比的秩最大为三，因此任务空间瞬时运动被限制在三维子空间内；对仅位置控制，该性质充分。若机构存在冗余，零空间中的关节运动不改变末端位置，可优化附加指标（如远离关节限位、回避障碍）。本文未利用零空间，因维数与实现复杂度在本科范围外。若评阅人提问，可答：可引入 \n(I - J^+ J) z 的零空间投影，以二次规划或投影梯度法在关节空间内同时满足主任务与次任务。

### 2.2 控制：离散时间实现与“步”概念

Coppelia 的 `step` 与连续时间控制理论中的采样周期类似，但内部子步和物理引擎迭代次数由引擎决定。将 `settle` 视为“控制周期内被控对象达到设定”的假设，在弱跟踪或高负载时可能不成立。提高仿真时间步细度、增强关节 P/D 或降低 `max_joint_step_rad` 是常见调参方向。

### 2.3 计算机视觉：颜色空间与光照

本实现工作于 RGB 阈值空间。对真实场景，HSV 对光照变化更鲁棒。可在 `buildTargetCubeMaskRgb` 前增加 `cvtColor` 到 HSV 并调整阈值。仿真中光强稳定，RGB 法足够。若加入方向光与阴影，阈值需重新标定。论文可附一张不同光照下的失败案例截图与改进说明，体现实验意识。

## 扩写卷二 第三章 实验方案建议（可放入“实验”章）

建议设计四组实验。实验 A 固定目标位置，改变 `damping_lambda`，记录迭代次数与终端误差。实验 B 固定控制参数，改变 `kMaxDescendFromHover`，统计是否发生桌面穿透或够不着。实验 C 对 `T_base_from_cam` 人为加小偏置，测试任务层限幅的鲁棒性。实验 D 将数值雅可比与 `simIK` 逆解或解析解速度对比，比较单点到达时间。每组至少三十次试验，报告均值方差。当前代码未内建自动记录，可添加 `ofstream` 以 CSV 输出。

## 扩写卷二 第四章 非功能需求：可维护性、可移植性、许可

可维护性方面，代码中大量魔数（如 512、511）应集中为命名常量。可移植性方面，手眼与相机文件路径为相对路径，工作目录假设在可执行文件旁；若从 IDE 以不同 cwd 启动会失败，可在 `main` 打印 `std::filesystem::current_path()` 并文档化。许可方面，Coppelia、OpenCV、ZMQ 与项目自身代码的许可证应分别列于论文附录，避免版权风险。

## 扩写卷二 第五章 对评阅常见问题的预备回答

问：为何不用 MoveIt？答：本课题训练目标为理解视觉—控制链路与 API 级编程，MoveIt 对本科项目可能黑盒化过多；但承认其在碰撞检测与规划上的优势，未来可迁移。

问：误差主要来自哪里？答：深度单点噪声、手眼标定、未去畸变、仿真关节跟踪误差与数值雅可比噪声的综合。

问：能否证明收敛？答：PBVS 在线性化与小步长下局部收敛；本文实现加入阻尼与步长裁剪，属于启发式稳定化，严格证明需参考连续时间分析和离散采样定理，本科论文可述而不证。
