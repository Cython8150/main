## 扩展卷终 C 开题与中期所要求的内容如何映射到本课题

许多高校在“开题报告”中要求：研究内容、技术路线、关键难点、进度安排与参考文献。研究内容可表述为：构建 CoppeliaSim 场景中的 UR5–RG2–视觉传感器系统；实现 RGB-D 颜色分割与深度反投影；估计手眼变换并完成基座坐标下的目标定位；实现基于数值雅可比与阻尼最小二乘的末端位置伺服；完成抓取—回零—分类释放任务闭环。技术路线即本文档所述模块串联。关键难点通常落在：坐标系一致性、差分雅可比计算代价与收敛性、线程同步与调试、释放阶段动力学切换。进度安排可按月份拆分：环境搭建、视觉标定、控制调试、论文撰写。参考文献在开题时列出骨架，在定稿前更新至三十篇以上并保持 GB/T 7714 格式一致。

## 扩展卷终 C 如何把仿真截图写成“实验现象描述”而不是流水账

每张截图应在正文里有一句“观察到什么”。例如：掩膜覆盖了立方体顶面且噪声斑点少于若干像素；PBVS 迭代结束时控制台误差小于阈值；释放后立方体落在色板附近。把现象与参数联系：当 `damping_lambda` 从 0.045 调整为 0.075 时，释放段迭代次数如何变化。没有数字时至少写“收敛更稳/更慢”的对比。这样写比连续贴图不解释更有学术味。

## 扩展卷终 C 把“系统测试”写进论文时的注意点

黑盒用例、白盒用例、回归测试、压力测试是软件工程词汇。本科论文可简化为“功能测试 + 失败注入测试”。例如临时把 `kMaxDescendFromHover` 设为零观察穿模，是失败注入。记录系统是否按预期返回错误信息并安全退出。注意：不要对共享机器做破坏性操作；仿真中改参数风险低。

## 扩展卷终 C 补充一 把 `jacobian_cartesian_control` 与经典教材公式的逐句对照写进论文的方法

在正文或附录中，可安排一个小节将 `dlsStep` 中的矩阵运算与教材中 \(\Delta \mathbf{q} = \mathbf{J}^\top (\mathbf{J}\mathbf{J}^\top + \lambda^2 \mathbf{I})^{-1} \mathbf{e}\) 的推导逐步对应：先指出代码里 `JJT` 的构造对应 \(\mathbf{J}\mathbf{J}^\top\)，再指出对角加 `lam2` 对应 \(\lambda^2 \mathbf{I}\)，再指出 `invJJT` 与 `w` 的乘法对应 \((\mathbf{J}\mathbf{J}^\top + \lambda^2 \mathbf{I})^{-1} \mathbf{e}\)，最后 `dq` 的累加对应 \(\mathbf{J}^\top \mathbf{w}\)。这种对照不需要增加新代码，却能把“会调包”提升为“能对照公式读代码”，对评阅人友好。若学校要求“理论联系实际”，此小节是低成本高质量的落点。

## 扩展卷终 C 补充二 把 `visual_module` 的互斥设计画成时序图的方法

在 Visio、draw.io 或 Mermaid 中，用两条生命线表示“主线程”和“视觉线程”，标注 `rgb_requested` 与 `depth_requested` 的置位/清除顺序，并标出 `wait` 与 `notify` 的配对。时序图能在一页内解释为何不会并发读传感器。若评阅人非软件背景，时序图比文字描述更直观。注意：Mermaid 在部分 Word 流程中需导出为图片再插入。

## 扩展卷终 C 补充三 把 `testGrab` 的异常路径写进“可靠性分析”

`createPrimitiveShape` 失败、视觉无效、平面未找到、PBVS 返回 `false` 等路径在代码中都有处理或打印。论文可列一张表：异常类型、检测方式、系统行为、是否可恢复。当前部分异常直接 `return 1` 退出进程，属于“ fail-fast ”策略；在持续运行系统里可改为重试或报警。对比分析能体现作者对鲁棒性有思考，而不只写“成功实现”。

## 扩展卷终 C 补充四 把“对比实验”写得像论文而不是课程报告

对比实验需要控制变量。例如只改 `damping_lambda` 而固定随机种子、固定目标位置，比较收敛迭代次数。一次只改一个主变量，其他保持默认。记录表格并给误差条或方差。若时间不足，做三组对比也比纯定性“感觉更好”强。写作时用“在控制…不变的前提下，改变…，观察到…”的句式，符合实验描述习惯。

## 扩展卷终 C 补充五 把“系统边界”写清楚以限制过度承诺

明确系统不处理：动态目标跟踪、多物体分拣队列、避障、力控插孔、非刚体。明确系统依赖：Coppelia 场景正确、标定文件存在、网络连接稳定。边界清晰能避免答辩委员提出超范围问题时的尴尬。若某条边界未来可突破，放在展望而非本文贡献。

## 扩展卷终 C 补充六 对“软件架构图”中各框命名与代码目录映射

建议框图包含：Remote API 层、视觉层、控制层、任务编排层、数据（标定文件）层。视觉层对应 `visual_module`；控制层对应 `jacobian_cartesian_control` 与 `control`；任务编排对应 `testGrab`；数据层对应 `calibration_results`。箭头标注数据流向：图像像素→三维点→基座坐标→PBVS→关节命令→仿真步进。命名保持与代码一致，减少读者映射成本。
