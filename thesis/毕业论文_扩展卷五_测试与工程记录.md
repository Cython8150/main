
## 扩写卷五 系统测试、记录表格与工程化建议

### 5.1 功能测试用例设计（黑盒）

从用户可见行为出发，可列出如下用例。用例 UT-01：启动仿真与客户端后，视觉窗口能够持续刷新 RGB 与深度显示，按 `q` 或 ESC 可退出视觉线程（若启用键盘）。用例 UT-02：在场景中固定颜色块于视场中央，运行主程序一轮，应完成抓取并释放到对应色板，控制台打印 PBVS 收敛信息。用例 UT-03：将目标置于视场外，视觉失败返回无效点，程序应清理线程并以非零码退出，而非死循环卡死。用例 UT-04：临时改名平面路径，释放阶段应捕获异常并打印未找到平面，主流程降级处理（当前代码打印警告并跳过动力学释放段落）。随着代码迭代，应维护一张用例与自动化脚本对照表；本科论文可截取其中三到五条作为“软件测试”附录。

### 5.2 回归测试与持续集成

若实验室提供 GitLab CI 或 GitHub Actions，可在无头模式下编译目标（跳过 GUI 显示线程）并进行静态检查。由于 Coppelia 仿真通常需要图形会话或许可证，完整 CI 不易部署；最低限度可使用 `clang-tidy` 或 `cppcheck` 做静态分析，确保无明显内存泄漏模式（本仓库以值语义与智能指针使用较少，多数依赖栈对象）。将构建指令写入 README，并在论文“附录”附可复制命令，体现工程完整性。

### 5.3 性能剖析建议

使用 `perf` 或编译器插桩可估计热点是否在远程调用、图像拷贝或矩阵运算。直觉上，远程 API 与仿真步进占据主导，优化方向包括减少差分雅可比列数（不可行）、减少 settle 步数、缓存上一次雅可比（有风险）。论文可仅给出定性判断而非_profile 图表，除非课程明确要求性能章节。

### 5.4 日志规范

建议在统一前缀下输出：`[VISION]`、`[PBVS]`、`[TASK]`，并包含仿真时间与关节角快照（可选）。当前代码已有 `cout`/`cerr` 混用，后续可封装日志级别。对答辩演示，彩色终端或 `less` 分页有助于快速定位失败环节。

### 5.6 异常场景清单

包括：标定文件缺失、分辨率变更、物体卡在夹爪外、物理穿透、远程连接断开。对每一类给出检测方式与恢复策略的文字描述，即使未完全实现，也可作为“展望”写入。

### 5.7 代码评审要点（可作为指导教师签字页附件）

是否检查数组越界、浮点比较容差、负数开方、矩阵求逆失败分支；是否在出错路径释放资源（线程停止、仿真停止）；是否避免在热路径频繁分配堆内存（图像 `clone` 次数）。选取两到三条结合具体行号在附录点评。

## 扩写卷五 调试手记风格段落（可与“心得体会”合并）

在开发早期，常见现象是“分割成功但抓取点偏移”。排查顺序建议为：第一，确认 `1.jpg` 中掩膜是否覆盖目标；第二，打印 `center_point` 在相机系与基座系数值，比较物体真实位置；第三，检查手眼 XML 是否对应最新标定；第四，临时关闭 `depth_offset` 与高度限幅观察偏差方向。另一常见现象是 PBVS 不收敛，优先检查阻尼与步长，其次检查是否接近奇异位形，再次检查 settle 步数是否不足以让关节跟上目标。此类手记写入论文可显著增加真实感与字数，但应避免流水账，采用条理化叙述。
